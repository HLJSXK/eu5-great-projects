# EU5 1.4 苏伊士运河原生施工接入记录

更新日期：2026-10-27。目标为本工作区 EU5 1.4 参考环境；实际运行版本变化时须复核原版脚本和地图数据。

状态：已实现“伟大工程完工后启动原生运河施工”。游戏内施工、通航和保存加载尚待验收；静态检查不能证明引擎行为。

## 行为约定

伟大工程实际完工 → 次日启动原生运河开凿 → 原生施工完成后通航。

- 保留原有工程部施工、仪式、建筑等级和奖励。
- 保留原版 `build_suez_canal` 决议，伟大工程路径只调用相同的 `start_canal_construction = { }` effect。
- 伟大工程路径不额外扣除决议的 200,000 gold，不额外套用该决议的时代、科技与领土门槛。原生施工自身的工期、资源消耗及完成奖励由引擎处理，仍需实测。
- 运河已开放或已有施工时不再启动，原版先开工、先完成以及奇观扩建均沿用原生状态。
- 拆除奇观不停止原生施工，也不关闭已通航运河。所有权变化后的施工和通行规则由引擎处理。
- 只有当前回调地点有 owner 时才启动；无主地点跳过，不引入月度重试或读档修复。

此约定取代旧方案“奇观完工直接开放、最后一级拆除关闭”。旧开放调用曾以 `TEMP crash isolation` 注释停用；本次删除该残留和拆除关闭调用。用户报告旧方案失败，但本仓库没有据此证明具体的引擎崩溃原因。

## 原版证据

`common/decisions/canal_construction.txt` 的苏伊士决议在国家上下文中执行：

```text
location:suez = {
    start_canal_construction = { }
}
add_gold = -200000
```

扣款与施工 effect 是两条独立语句。原版决议要求拥有或合格非主权臣属拥有 `tinnis`、`suez`，研究 `suez_canal_advance`，并检查尚未开放和没有施工。这些要求保留在原版决议中。

官方 `docs/effects.log` 将 `start_canal_construction` 声明为 location scope；`docs/triggers.log` 同样将 `has_canal_construction` 和 `is_canal_open` 声明为 location scope。本实现从现有 location event 调用；与原版国家根作用域的实际差异仍需游戏内对照验证，不伪造 generic-action actor。

地图依赖 `.eu5-base/reference_game_files/game/in_game/map_data/adjacencies.csv` 中的原生 canal 邻接：

```text
bardawil_coast;gulf_suez;canal;suez;9168;5106;9173;5029;Suez Canal - TBD pixel coords from map team
```

`suez` 是 through-location。脚本启动施工不能凭空创建地图邻接；本 mod 不覆盖该地图文件。

## 接入点与生成归属

`data/unique_wonders.yaml` 保留现有声明：

- key：`unique_suez_ancient_canal`；ID：129。
- 固定地点：`suez`；`native_canal: true`，仅苏伊士启用。
- 完成建筑：`tv_wonder_unique_suez_ancient_canal_inaugurated`。
- 基础机制：`large_canal_system`；初始等级 0；三种仪式沿用统一仪式系统。

`gen_tv_wonder_finalization_effects.py` 在现有最终建筑 `on_construction_ended` 排队的一天延迟隐藏事件中，先同步真实建筑等级，再执行：

```text
if = {
    limit = {
        this = location:suez
        exists = owner
        location_building_level = {
            building_type = building_type:tv_wonder_unique_suez_ancient_canal_inaugurated
            value >= 1
        }
        is_canal_open = no
        NOT = { has_canal_construction = yes }
    }
    start_canal_construction = { }
}
```

次日检查避免建筑完成回调同 tick 的等级提交时序问题。以原生开放／施工状态防止重复任务，不额外记录“已启动”变量；因此新建、扩建或重建进入同一回调时，均不会重启已有施工。中间模块、仪式选择、悬停预览、普通地点显示刷新均不会启动运河。

拆除回调仍同步建筑等级、撤销失效仪式、维护优先工程和刷新显示；仅移除 `set_canal_open = no`。GP 源码不再直接调用 `set_canal_open`。

| 输入／生成器 | 产物 |
| --- | --- |
| `gen_tv_wonder_finalization_effects.py` | `src/in_game/common/scripted_effects/tv_wonder_finalization_effects.txt` |
| `gen_tv_engineering_department_wonder_mechanics_effects.py`，由 `gen_tv_wonder_location_display_effects.py` 调用 | `src/in_game/common/scripted_effects/tv_wonder_location_display_effects.txt` |

归属以 `data/generated_files.yaml` 为准。玩家说明明确额外开凿阶段、无需额外支付决议费用和拆除不关闭运河。产物保持 UTF-8 BOM。

本次没有新增 generic action，也没有修改原版决议。未来若新增按钮 action，仍须完成 AI list、message type 与五个通知字段注册。
